# Архитектура и режимы исполнения

## Состав

Два production targets: `SpotifyCarWidget` (app) и `SpotifyWidgets` (один extension с тремя независимыми Widget configurations). Тестовый target использует приложение как test host. Общие Swift-файлы входят в оба production targets; это отдельные процессы со своими actor instances. Swift package dependencies отсутствуют.

`PlaybackViewModel` работает на MainActor, публикует UI state, отменяет устаревшую UI-задачу, обновляется при активации сцены. `SpotifyPlaybackService` — actor, единая точка чтения, команд, смены режима и logout. Его можно создавать с отдельными `SharedStore`, `TokenStoring`, `HTTPClient`, `AppConfiguration`; тесты не требуют настоящего Spotify или Keychain.

`HTTPTransport` отделяет URLSession от декодирования и управления HTTP. `TokenManager` хранит в памяти только рабочие значения и читает актуальный token item из Keychain перед запросом. Сервис удерживает межпроцессную блокировку во время token exchange / refresh и команды, поэтому app и extension не вращают один refresh token одновременно.

## Хранилище

Full: App Group container с атомарным `playback.json`, `playback.lock`, `Artwork/*.jpg`. Один `StoredPlayback` объединяет mode и snapshot: переключение источника не оставляет новый mode со старым снимком. Tokens в этом файле отсутствуют. Отдельный Keychain access group одинаков у app и extension. Запись JSON — atomic, файловая защита `completeUntilFirstUserAuthentication`, Keychain — `AfterFirstUnlockThisDeviceOnly`. До первого unlock после reboot реальный доступ не гарантируется.

`flock` берётся неблокирующими попытками с async sleep и пределом ожидания 6 секунд. Это не вечный цикл: при недоступной блокировке операция завершится ошибкой busy. При смерти extension OS освобождает lock. Блокировка держится на время сетевой операции, конкурирующие действия могут получить busy; пользователь повторяет действие позже. Читатели видят целый предыдущий или новый JSON, никогда половину записи. HTTP requests имеют timeout, фоновые worker-процессы не создаются.

Если полный App Group container недоступен, сервис показывает ошибку подписи/хранилища. Он не переходит незаметно на обычный UserDefaults и не заявляет работающую синхронизацию.

Personal: `PERSONAL_DEMO` на уровне compile conditions, пустой entitlement plist. App и extension используют каждый свой Application Support/PersonalDemo. OAuth отключён даже при заполненном Client ID. Это намеренно ограниченный вариант без дополнительных capabilities для переносимой переподписи. App Groups / Keychain Sharing сейчас отмечены Apple доступными также бесплатному Apple Developer, но Associated Domains для HTTPS OAuth — нет. Независимые хранилища Personal являются выбором совместимости проекта, а не доказательством недоступности App Groups. Настройки темы в AppStorage относятся только к UI; tokens туда не попадают.

## Обновление

При старте, возврате в foreground и ручном refresh выполняется чтение источника. Несколько одновременных refresh одного actor делят `Task`; межпроцессные запросы в пределах 2 секунд после успешного снимка также используют кеш. Отмена refresh при переключении режима и logout не позволяет устаревшему ответу перезаписать новый источник: все изменения проходят под одной блокировкой, перед commit проверяется cancellation.

TimelineProvider делает одно ограниченное обновление и создаёт одну entry; reload policy `.after` запрашивает обновление не раньше чем через 15 минут. Длинный `Retry-After` сдвигает эту дату. WidgetKit вправе отложить его ещё дальше. Reload после команды/foreground — просьба системе, не гарантия мгновенного рендера.

Виджет не содержит таймера, URLSession polling, фонового аудио, live waveform или обхода WidgetKit budgets. Последний реальный progress не экстраполируется: трек мог закончиться, пользователь мог переключить его на другом устройстве. `serverTimestamp` сохраняется для диагностики, `observedAt` — время последнего успешного получения снимка. Ошибка не выдаётся за успешное обновление, stale определяется по наблюдению старше 5 минут. В активном UI только демо имитирует секунды; реальные значения остаются снимком.

## Команды и сбои

App Intents выполняются без запуска приложения. Они читают текущий mode внутри lock. Демо-команда меняет только локальное демо. Реальная команда сначала делает GET playback, проверяет активность устройства и `actions.disallows`, затем отправляет команду. Play/Pause определяется из свежего ответа, а не из потенциально старой timeline. После успеха — одна задержка 400 ms и одно чтение; порядок применения команд Spotify асинхронен, поэтому полученный снимок иногда может ещё отражать предыдущее состояние.

GET после временных сетевых ошибок/5xx повторяется максимум дважды, с экспоненциальной задержкой и jitter для 5xx. POST next/previous и PUT play/pause не повторяются после сетевых/5xx сбоев: неизвестно, применил ли сервер команду. При 401 сервер отверг запрос, поэтому допускается один повтор после обновления token. 403 — actionable error про Premium/allowlist/scopes. 404 — отсутствие активного устройства. 204 GET и null item — отсутствие playback; episode/ad/unknown не выдаются за музыкальный трек.

В Widget Extension выбран отдельный HTTPClient без повторов GET и с request/resource timeouts 3/4 секунды, чтобы уменьшить риск исчерпания времени extension. Правило одного refresh после 401 сохраняется. Обложки в extension также имеют сокращённое ожидание. Это не гарантия того, что iOS никогда не завершит extension; при плохой сети полезен локальный снимок.

429 не приводит к sleep на всё время Retry-After: дата сохраняется на диске и соблюдается другими экземплярами сервиса. Переключение демо не удаляет Spotify cooldown. Никаких попыток обхода лимитов или перебора устройств нет.

## Изображения и интерфейс

Обложки принимаются по HTTPS с `scdn.co`; поток ограничен 4 MB до декодирования, ImageIO создаёт thumbnail максимум 480 px, JPEG сохраняется локально. Ограничения кеша: 12 MB и 40 файлов, удаление по возрасту записи. Это ограниченный FIFO по времени создания файла, не постоянное скачивание и не неограниченный memory cache. Widget views читают только локальные изображения; fallback — music.note.

Оригинальные демо-PNG генерируются Node-скриптом, входят в asset catalog app и extension, не зависят от сети. Официальный значок Spotify и его источник описаны в Assets/THIRD_PARTY.md. Реальная обложка не перекрывается текстом и не обрезается. Card content остаётся читаемым, когда система удаляет `containerBackground`: artwork является содержимым, а основной фон обозначен отдельно. Cover Focus demo использует собственную художественную композицию, не анализ аудио.

CarPlay не выделяется через неофициальную проверку окружения: обе компактные адаптации работают в systemSmall, а wide controls выбирается только по widgetFamily == systemMedium. View использует системные margins. Подтверждение конкретных размеров, fullColor/vibrant и VoiceOver — часть ручной проверки на Xcode/устройстве.
